\section*{Tests}

%% =============================================================================
\subsection*{Correctness Tests}\label{subsec:correctness_tests}
%% =============================================================================

The correctness suite resides in \noindent\textit{\small Folder: \texttt{CHC-Verification/correctness\_tests}} and is executed with
\texttt{pytest}, using \texttt{pytest-xdist} for parallel execution, over \texttt{unittest.TestCase}-based test classes.  The fixture set contains
\textbf{64} \texttt{.tl} programs shared across all test modules, covering a wide range of semantic
properties and edge cases.  These fixture programs can be found in
\noindent\textit{\small Folder: \texttt{CHC-Verification/correctness\_tests/programs/}}.
%% ---
\subsubsection*{Test Modules}

\begin{longtable}{p{0.22\textwidth} p{0.72\textwidth}}
\toprule
\textbf{File} & \textbf{Role in evaluation} \\
\midrule
\endhead
\bottomrule
\endlastfoot
\texttt{test\_default.py}   & Validates concrete-start-state verification in \texttt{default} mode,
  covering arithmetic invariants, geometric bounds, pen state, directional and heading-grid checks,
  trigonometric motion, and advanced nested control-flow fixtures. \\[4pt]
\texttt{test\_specific.py}  & Validates parameterised initialisation in \texttt{specific} mode, with
  boundary-sensitive outcomes under user-supplied parameter dictionaries; exercises countdown,
  accumulate, chain, two-param, loop-move, nested conditional, and pen-conditional programs. \\[4pt]
\texttt{test\_universal.py} & Validates symbolic/unconstrained initialisation in \texttt{universal}
  mode, API-level validation errors, heading-grid safety queries, pc-scoped (\texttt{at\_pc}/
  \texttt{upto\_pc}) and terminating-scope properties across arithmetic, geometric, pen, and heading
  categories. \\[4pt]
\texttt{test\_semantics.py} & Validates the semantic-helper transpiler
  (\texttt{semantic\_properties.py}) at two levels: (i)~unit tests that assert the
  \texttt{transpile\_property\_expr} function converts every built-in helper call to the correct Z3
  expression string; (ii)~end-to-end integration tests that invoke \texttt{CHC\_Verification} with
  helper-style property strings across all three modes (default, specific, universal). \\[4pt]
\end{longtable}

\noindent
Crucially, the timeouts reflect a \emph{solver scalability} limitation, not a
defect in the encoding logic.  The affected programs are correctly translated
into CHC rules, and the properties are well-formed; \textsc{Spacer} simply
cannot synthesize a sufficiently strong inductive invariant within the
configured timeout when both heading normalization and trigonometric
approximations are present in the same fixed-point system.

\subsubsection*{How to Run}

The correctness suite is driven by \texttt{pytest} from the \texttt{CHC-Verification/correctness\_tests/} directory.
Parallel execution via \texttt{pytest-xdist} (\texttt{-n auto}) is recommended.

\begin{lstlisting}[style=terminal, language=bash]
# runs all tests in parallel
pytest -n auto -q 

# one module only
pytest -n auto -q <test_module.py>

# one test case
pytest test_semantics.py::TestSemanticPenUniversal::test_branch_pen_terminating_guarded_relation_pass -q
\end{lstlisting}

\subsection*{Performance Tests}
\label{sec:performance_tests}
%% =============================================================================

The CHC verification pipeline is benchmarked to stress-test solver scalability under
various optimisation levels and hint configurations.  The test suite resides in
\noindent\textit{\small Folder: \texttt{CHC-Verification/performance\_tests}} and is executed with
\texttt{pytest} using \texttt{pytest-xdist} for parallel execution.

The fixture contains 24 \texttt{.tl} programs across the three modes and cover cases that can blow up the number of solver constraints. 
The fixture programmes can be found in \noindent\textit{\small Folder: \texttt{CHC-Verification/performance\_tests/programs/}}. 
Each test case is evaluated under \textbf{six configurations} formed by crossing two
optimisation levels with three hint modes (detailed in the \emph{Hint Configurations} subsection).
Timing data are written to \texttt{perf\_results\_\{default,universal,specific\}.csv}.

\subsubsection*{How to Run}

The correctness suite is driven by \texttt{pytest} from the \texttt{CHC-Verification/correctness\_tests/} directory.
Parallel execution via \texttt{pytest-xdist} (\texttt{-n auto}) is recommended.

\begin{lstlisting}[style=terminal, language=bash]
# runs all tests in parallel
pytest -n auto -q 

# one module only
pytest -n auto -q <test_module.py>
\end{lstlisting}
